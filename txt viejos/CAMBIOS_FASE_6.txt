FASE 6 – ADMINISTRACIÓN DEL SISTEMA Y SOLUCIÓN DE RUTAS PÚBLICAS

1) Corrección del error de red con Ngrok
- Se detectó la causa raíz del Network Error: el frontend estaba intentando llamar al backend con una URL como http://<ngrok-domain>:8000.
- Ese puerto no existe como endpoint público en Ngrok; por eso el navegador fallaba en la petición AJAX del login.
- La solución fue centralizar el consumo de API mediante un proxy local de Vite y dejar la base URL del frontend como /api.
- Se configuró Vite Server con allowedHosts: true y proxy /api -> http://localhost:8000.
- Se limpió el túnel antiguo para evitar ERR_NGROK_334 y se reinició ngrok con la cabecera de advertencia.

2) Login por C.I. y contraseña simple
- El endpoint de autenticación acepta ahora usuario por C.I., correo o nombre completo.
- La validación usa la lógica de hash real del sistema y sigue permitiendo usuarios activos/inactivos.
- El login del frontend usa el campo usuario en lugar de correo institucional y agrega el botón de mostrar/ocultar contraseña.
- La contraseña de prueba del sistema quedó en 12345 para usuarios admin, bioquímica e interno.

3) Panel administrativo del sistema
- Se creó una UI de administración para el rol ADMIN con acceso a:
  * Gestión de usuarios: alta, edición, activación/desactivación, reset de contraseña.
  * Auditoría del sistema: trazabilidad de enmiendas y cambios registrados en la BD.
- La administración solo está disponible para usuarios con rol ADMIN.

4) Backend administrativo
- Se implementaron endpoints protegidos:
  * GET /admin/usuarios
  * POST /admin/usuarios
  * PUT /admin/usuarios/{id_usuario}
  * PUT /admin/usuarios/{id_usuario}/reset-password
  * GET /admin/auditoria
- El password se almacena con hash usando pwd_context.hash(password) antes de persistirlo.
- La respuesta nunca expone hash_password ni secretos internos.

5) Estructura frontend creada
- frontend/src/pages/admin/GestionUsuariosPage.tsx
- frontend/src/pages/admin/ModalUsuario.tsx
- frontend/src/pages/admin/HistorialAuditoriaPage.tsx
- frontend/src/services/adminService.ts

6) Verificación realizada
- Backend: pytest autenticación con CI pasó correctamente.
- Frontend: npm run build compiló sin errores.
- Login por túnel: la validación contra https://uncommon-sample-second.ngrok-free.dev/api/auth/login devolvió un JWT válido.
- Admin: GET /api/admin/usuarios con token de administrador devolvió la lista de usuarios correctamente.

7) Estado final
- El sistema quedó preparado para operar con un único túnel ngrok y con administración centralizada del usuario admin.
- La solución es estable y lista para uso operativo con acceso protegido por JWT.
